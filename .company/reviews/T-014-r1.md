# T-014 review r1 — W-5 "Shift and rhythm" (+ Addendum tap-to-replay, fix-r1)

## Blocking issues

1. **src/styles/56-marquee.css:1 — the marquee blows out the desktop page layout at >= 1024px (page goes blank / ~7,500px wide).**
   Repro: headless Chromium at 1440x900 (and 1280), scroll Stack into view. Measured: `document.documentElement.scrollWidth = 7548` at 1440 (7527 at 1280). `main`'s grid track grows to 7548px, every `.container` is centred at x ~= 3174, and the viewport shows only background (shot `.company/qa/shots/T-014-marquee-dark-1440.png`).
   Cause: on desktop `main` is a grid (T-015 spine layout), and `#skills` is a grid item with the default `min-width: auto`. `overflow-x: clip` does not make an element a scroll container, so the section's automatic minimum size still includes the marquee rows' `max-content` width (~9,000px). It doesn't show up at load because `content-visibility: auto` skips the marquee's layout while it is offscreen. That is why the ticket's "no overflow" check and Codex's report missed it. 360–768 is fine.
   Fix: in `src/styles/56-marquee.css`, change line 1 to `#skills { overflow-x: clip; min-width: 0; }`. Also add `contain: inline-size;` to the `.js .marquee { ... }` rule as a guard. Either change alone fixes it; I verified both by injection, and scrollWidth went back to 1440 at 1440. Add a test assertion to `test/wow-css.test.mjs`: the CSS contains `min-width: 0` on `#skills` (or `contain: inline-size` on `.js .marquee`).

## Non-blocking suggestions

- `src/scripts/60-motion.js`: Codex collapsed the whole file onto one line (2,997 B, presumably to stay under a 3,000 B cap). It works, but the diff is now unreviewable and later edits will be painful. Next time, either raise the cap by the ~100 B the handler needs, or keep the original line breaks.
- Replay guard semantics changed slightly. The old guard was `canAnimate()` (hero visible and not paused). The new one is `!motion-paused && !is-idle`, and it only runs under `html.motion`, so reduced motion gets no replay. That is equivalent in practice and fine.
- The header mark (`.brand__mark`) has no hover shift. Spec §7.1 covers only `.sc-hero`, so this is not a defect. If the owner wants the header logo to shift too, that needs its own small ticket: the header SVG uses `<use>` clones, not `.sc-part` groups.
- Out of scope (T-013): at 1024/1280, during the first load, `.tl__card.is-revealing` produces a transient 16–24px horizontal overflow (cards slide in from offscreen). It is unrelated to T-014. Consider `overflow-x: clip` on `.tl`.
- At rest, `.sc-hero__glow` now has opacity .75 everywhere, including reduced motion and no-JS (before it was 1). This is per spec and looks fine.
