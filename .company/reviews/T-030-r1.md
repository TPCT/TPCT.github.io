## Blocking issues

1. `src/styles/40-hero.css:52-53` (inside `@media (min-width: 768px)`): the GitHub ghost CTA overlaps the hero visual from 1024px to about 1230px.
   - Cause: `.hero__ctas { flex-wrap: nowrap; width: max-content; max-width: calc(100vw - 2 * var(--gutter)); }` together with `.btn { flex-shrink: 0 }`. From 1024px the `.hero__text` column is only `grid-column: 1 / 8` (~550px at 1024), but the three buttons need 237 + 240 + 165 + 2×12 = 666px. The row runs out of its column and goes underneath `.hero__visual`.
   - Measured at 1024: ghost button x 533–699, `.hero__text` right edge 582, `.schematic` card x 606–992 / y 470–674. At 1100 the ghost overlaps `.sc-hero`, `.schematic` and `.schematic__domains`. The schematic card is painted on top, so "GitHub" is cut to "Gi" and mostly can't be clicked. See the scratchpad shot `hero-1024.png`: the button is visibly hidden behind the domains card.
   - This happens on every common laptop width (1024–1229).
   - **Fix:** in the `min-width: 768px` block, delete `.hero__ctas { flex-wrap: nowrap; width: max-content; max-width: ...; }` and the `flex-shrink: 0`. Keep the base rule `.hero__ctas { display: flex; flex-wrap: wrap; gap: 12px; }`.
     - Result: the row stays on one line wherever the column fits it (768–1023, where the grid is single-column and the text is ~704px wide, and ≥ ~1230).
     - Between 1024 and ~1230 the ghost wraps to a second line inside the text column. That matches the ticket's "nowrap there if they fit".
   - Add a test asserting that `40-hero.css` has no `width: max-content` on `.hero__ctas`.
   - Re-verify at 1024/1100/1280 that the ghost button's right edge is ≤ the `.hero__text` right edge.
