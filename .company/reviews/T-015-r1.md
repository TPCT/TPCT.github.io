T-015 — Vertical rhythm + section continuity. Review r1 (2026-10-21).

The rhythm change works well. The section gaps went from 272px to 75px at 1440 and from 165px to 48px at 375. The spine, chapter nodes, connectors and scroll cue render correctly in both themes, and there is no overflow and no console or CSP error. ## Blocking issues

1. `src/scripts/62-spine.js:6`: the spine progress uses the wrong reference, so the draw effect is never visible.
   - The progress is `(innerHeight - main.top) / main.height`, but the spine does not start at the top of `main`. It starts after the hero (~990px lower at 1440) and is shorter than `main`.
   - Measured at 1440×900, the bottom of `.spine__fill` relative to the viewport (vh = 900):

     | scrollY | fill bottom |
     |---|---|
     | 0 | 1732 |
     | 1200 | 1612 |
     | 3000 | 1432 |
     | 5000 | 1232 |
     | 7000 | 1033 |
     | 8500 | 883 |
     | 9300 | 632 |

   - So for about 90% of the page, every on-screen part of the spine already looks fully drawn. The violet line never visibly "draws down as you read", which was the main continuity cue in the ticket.
   - **Exact fix:** compute the progress against the spine element itself and pin the drawing point inside the viewport. For example:
     ```js
     const sp=document.querySelector('.spine');if(!sp)return;const m=sp.parentElement;
     ...
     const u=()=>{r=0;const b=sp.getBoundingClientRect();m.style.setProperty('--spine-progress',q.matches?1:Math.max(0,Math.min(1,(innerHeight*.6-b.top)/b.height)))};
     ```
     This keeps the end of the fill at about 60% of the viewport height while you scroll through the sections.
   - Dropping the `main:has(> .spine)` selector also stops this script from throwing a SyntaxError in browsers without `:has()`.
   - Update the test in `test/scripts.test.mjs` to match: stub `document.querySelector` to return a spine `{ getBoundingClientRect, parentElement: main }`. Then assert progress 0 when spine.top ≥ 0.6·vh, about 0.5 at the midpoint, 1 past the end, and 1 under reduced motion.
   - Keep the file ≤ 700 B.

When T-013 adds Journey (9 sections), the spine will stop one section before Contact. Either change both values in T-013 (`repeat(9, auto)` and `2 / 10`), or avoid counting sections altogether. One way: drop `grid-template-rows` and use `grid-row: 2 / -1` with `grid-auto-rows: auto`, then add a test that asserts the spine's bottom is at or below `#contact`'s top. Note this in the T-013 ticket at the least.

The ticket asked for both, but it brings back the "big gap" feeling at the very end. Consider dropping one of them.

- The `is-lit` logic in `60-motion.js` adds and then immediately removes the class for pending elements. It works, but it would read more clearly as `if (pending) … else add('is-lit')`.
