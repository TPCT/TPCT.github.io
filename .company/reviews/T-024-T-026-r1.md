## Blocking issues

### B1 (T-024) The kinetic letter rise plays under the intro curtain, so first-time visitors never see it
- File: `src/scripts/81-kinetic.js:20` (`const delay=Math.max(0,(e.classList.contains('intro')?0.72:0.10)-performance.now()/1000)`).
- Problem: the GSAP delay is measured from navigation start (`performance.now()`), but the CSS curtain (`intro-out`, 700ms delay) is measured from when its style is first resolved, which is first paint at about 250 to 450ms. On top of that, `expo.out` does most of its travel in the first ~20% of the tween. Here is what I measured in headless Chromium at 1440×900 (perf-time ms, last letter's translateY):
  - run 1: curtain `intro-out` starts 862, ends 1188. Letter at y=91 at 945, y=15 at 1190, settled 1480.
  - run 2: curtain starts 1117, ends 1429. Letter already at y=17 (87% opaque) at 1085, settled 1431.
  - The curtain wipes bottom-up (`clip-path: inset(0 0 100% 0)`), so the h1 near the top is uncovered last. The screencast frames (`.company/qa/shots/T-024-first10s.webm`, ~1.0 to 1.3s) show the name appearing already settled.
  - Repeat visit / deep link: fine. Letters rise from about 540ms, after first paint at 452.
- Exact fix: in intro mode, anchor the timeline to the curtain, not to navigation start. In `81-kinetic.js`, keep the split as it is, then:
  ```js
  const intro=e.classList.contains('intro');
  const a=intro&&document.querySelector('.intro-screen')?.getAnimations().find(x=>x.animationName==='intro-out');
  // start ~120ms after the curtain begins to lift; fall back to the old perf-based delay if no animation is found
  const delay=a&&a.startTime!=null
    ? Math.max(0,(a.startTime+700+120-document.timeline.currentTime)/1000)
    : Math.max(0,(intro?0.72:0.10)-performance.now()/1000);
  ```
  - `startTime` may still be null at DOMContentLoaded. If so, `await a.ready` (or wait one `requestAnimationFrame`) before creating the timeline. Apply `B.g.set(chars,{yPercent:118,rotationX:-88,opacity:0.001,transformOrigin:'50% 100% -12px'})` synchronously, so letters never flash in place.
  - The CSS watchdog (`--kinetic-wait`) still covers the no-GSAP path.
- Acceptance for the fix: in the browser check, log `animationstart` of `intro-out` and the last `.ch` transform per rAF. The last letter must still be ≥ 50% of its travel away (`translateY` ≥ 60px at 1440) when `intro-out` starts, and settle no later than 2.8s perf-time. Add this measurement to the T-024 browser check.

### B2 (T-024) Two roles render on top of each other for the first ~2.4s (garbled text in the hero)
- File: `src/styles/44-intro.css`, rotator block (`.js .roles li:nth-child(3) { animation-delay: calc(var(--roles-start) - 3s); }`). This was copied verbatim from ux-bold §4.4; the spec itself is wrong.
- Problem: with `--roles-start` = S, role 3's cycle phase S−3s makes its 0–26% "visible" window fall at S−3s … S−0.66s. Role 1 is also visible during that time (backwards fill of its 0% keyframe).
  - Measured: computed opacity is 1.00 for both "CEO @ ShiftCodes" and "Senior Full-Stack Engineer" at 200, 800, 1100 and 1500ms (intro run), and at 250ms (repeat-visit run).
  - Screencast frame at ~1.6s shows the two strings overprinted ("CEO @ Full-Stack Engineer" mush), right under the name, during the wow moment.
  - This violates the acceptance item "first role visible immediately… 3 roles occupy one grid cell" (one at a time).
- Exact fix: add a hold animation that keeps roles 2 and 3 invisible until the rotator starts. This leaves the later phase and the flip-ins unchanged. Inside the existing `@media (prefers-reduced-motion: no-preference)` block in `44-intro.css`:
  ```css
  @keyframes role-hold { from, to { opacity: 0; } }
  .js .roles li:nth-child(n+2) { animation: role-cycle 9s var(--ease-in-out) infinite both, role-hold var(--roles-start) linear; }
  .js .roles li:nth-child(2) { animation-delay: calc(var(--roles-start) - 6s), 0s; }
  .js .roles li:nth-child(3) { animation-delay: calc(var(--roles-start) - 3s), 0s; }
  ```
  - The `.motion-paused .roles li { animation: none; }` rule already clears both animations. Keep `role-hold` inside the no-preference gate; `wow-css.test.mjs` checks this.
  - Add a test assertion in `test/bold-hero.test.mjs` that `role-hold` exists inside the gate.
  - Add a browser assertion: at 200ms, 1500ms and 3000ms (intro and no-intro), exactly one `.roles li` has computed opacity > 0.5 outside the 0.36s cross-flip windows.

## Non-blocking suggestions
1. `81-kinetic.js` bail-out was lowered from 1400 to 800ms (and `--kinetic-wait` from 1600 to 800ms) to satisfy the fix-r1 timing test.
   - On a cold mobile load from GitHub Pages, DOMContentLoaded at > 800ms is common. Those visitors get the CSS `word-up` fallback instead of the 3D letters.
   - Consider a cutoff around 1100ms. Change the timing test so it bounds the fallback path (≤ 2800ms) and the kinetic path's start-to-settle (duration + stagger × (n−1)) separately, instead of `cutoff + duration`. This becomes more relevant after B1, because the intro start is anchored to the curtain.
2. `81-kinetic.js` `revert()`:
   - It leaves `style=""` on the accent span (seen after revert: `<span style="">Elsayed</span>`). After `removeProperty('--ww')`, call `if(!w.getAttribute('style'))w.removeAttribute('style')`, as `80-bold.js` does.
   - `--cx` is never removed, but the `.ch` nodes are discarded, so that is harmless.
3. `40-hero.css`, last line of the entrance block: `.js .hero h1.is-kinetic .w > span, .hero h1.is-kinetic .w > span` repeats the same rule. One selector, `.js .hero h1.is-kinetic .w > span`, is enough to win the cascade. Keep the test hook string.
4. Vendor-abort noise is harmless. With `/assets/vendor/**` aborted, the only errors are 2× `Failed to load resource: net::ERR_FAILED` (gsap, ScrollTrigger), with no `pageerror` and no CSP violation. The h1 is fully risen via CSS `word-up` by 3.0s, and `html.bold` is never set. No action needed.
5. T-026, mobile 375: after an instant jump from the hero straight to `#work`, the tint read 0.22/0.54/0 at +1.4s.
   - Stepping section by section converges exactly to the table (mobile and desktop light: experience 1/.25/0, work .2/1/0, contact .45/.8/1 at both +1.4s and +3s).
   - QA should re-check direct deep jumps (e.g. nav click on mobile) settle to the target mood. If not, call `mood(id)` from `onRefresh`/`onUpdate` of the active trigger.
6. `83-atmos.js` is a single 2,391-byte minified line, 9 bytes under budget. It is hard to review and maintain. Future atmosphere work will need either a budget bump or moving the split helper out.
