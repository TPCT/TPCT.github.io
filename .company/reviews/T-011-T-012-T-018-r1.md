## Non-blocking suggestions
1. `src/scripts/71-decode.js` (prepare step) — `.dc-src` is appended after any element children, so an element with mixed content (element + text) would be reordered. All current targets (`.hero .eyebrow`, `.roles li`, `.section-head__index`, `#primary-nav a`) hold plain text only, so there is no visible effect today. If a future target gets child elements, insert the wrapper at the first text node's position (`firstText.before(s)`) instead of `el.append(s)`.
2. `src/scripts/72-spot.js` — adds a `MutationObserver` on `<html>` attributes so that toggling pause drops `is-spot` at once (not only on the next pointermove). This is extra to §5.2 but small, within the 900-byte cap, and correct. Keep it.
3. `src/styles/61-cards-live.css` — the deviation from the ux-wow §5.1 verbatim CSS (`.motion` prefix on the two `rim-spin` rules, plus `.motion-paused .card::before { opacity: 0 }`) is justified by the ticket's "No-JS: no spin" and "Pause: spotlight off" criteria. Back-port it to `.company/ux-wow.md` §5.1 so that the spec matches the code.
4. T-018 / Lighthouse SEO 92: the only failed audit is `robots-txt` ("unable to download"). Lighthouse fetches `/robots.txt` from the page context, and the site's CSP `connect-src 'none'` blocks that fetch. `curl` returns a valid file. Crawlers are not affected, but PageSpeed Insights will show the same 92 in production. Optional fix (lead decision): `connect-src 'self'`. It costs nothing security-wise for a static site, and it changes no hash.
5. T-018: the Codex report says `test/build.test.mjs` failed (empty CLI stderr). In this tree, the full `node --test` run passes (build tests included), so that was a transient tree-state issue. No action.
6. `src/lib/validate.mjs` — when `contact.linkedin` is missing, there are three errors (required, protocol, LinkedIn shape). That is acceptable, but the shape check could be skipped when the value is not a string, to reduce noise.
