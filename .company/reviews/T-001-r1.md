## Blocking issues

### B1. Skip link can never receive focus (ux §4.1, US-02)
`src/styles/30-header.css:28-29` (last two lines):
```css
.skip { visibility: hidden; }
.skip:focus { visibility: visible; }
```
Elements with `visibility: hidden` are taken out of the tab order, so `.skip:focus` never matches. Verified: the first Tab at 320/360/768/1024/1440 goes to `.brand`, not the skip link.
**Fix:**
- Delete both lines.
- On line 1, change the hidden transform from `transform: translateY(-120%);` to `transform: translateY(calc(-100% - 16px));`. That clears the 12px top offset fully, so no sliver shows, and you do not need `visibility`. Keep `.skip:focus { transform: translateY(0); }`.
- Add to `test/build.test.mjs`: `assert.doesNotMatch(css, /\.skip\s*\{[^}]*visibility:\s*hidden/);`

### B2. Mobile menu closes on any focus move inside it, so menu links do not work (ux §4.2)
`src/scripts/20-nav.js:29-33`. `queueMicrotask` runs during the `focusout` dispatch, before the new element is focused. At that moment `document.activeElement` is `<body>`, so `close(false)` runs every time focus moves, even from one menu link to the next. Verified at 360px:
- Open the menu (focus goes to "About"), press Tab: the menu closes (`aria-expanded="false"`, nav `hidden`) and focus drops to `<body>`.
- Open the menu, click "Work": mousedown moves focus, the menu closes before the click lands, and no navigation happens (`location.hash` stays `""`).

**Fix:** replace the whole `header.addEventListener('focusout', …)` block with:
```js
header.addEventListener('focusout', function (e) {
  if (button.getAttribute('aria-expanded') !== 'true') return;
  const to = e.relatedTarget;
  if (to && !nav.contains(to) && to !== button) close(false);
});
```
A null `relatedTarget` (click on a non-focusable area, or Safari not focusing links on click) is left to the existing outside-click handler.

### B3. Mobile menu panel shows open on first paint until `site.js` runs, and stays open if it fails to load
The inline theme script swaps `no-js` to `js` at once. Before deferred `site.js` runs, `#primary-nav` is not `hidden` yet, so at base width it renders as the absolute dropdown over the hero. Verified with `site.js` delayed 1.5s at 360px: nav `display:block`, top 55px, height 281px, covering the hero. On a real network this flashes on every mobile load. If the script fails, the panel covers content for good and has no close button.
**Fix:**
- In `src/styles/30-header.css`, after the `#primary-nav { position: absolute; … }` rule, add:
  `.js .site-header:not([data-nav-ready]) #primary-nav { display: none; }`
- Inside the existing `@media (min-width: 768px)` block, add:
  `.js .site-header:not([data-nav-ready]) #primary-nav { display: block; }`
- In `src/scripts/20-nav.js`, directly after the `resize();` call, add:
  `header.setAttribute('data-nav-ready', '');`
- Add to `test/build.test.mjs`: `assert.match(css, /\.js \.site-header:not\(\[data-nav-ready\]\) #primary-nav\s*\{\s*display: none;/);`

## Non-blocking suggestions
1. `src/content.json` was re-serialised (`JSON.stringify(…, 2)`), not copied byte-for-byte. Inline arrays/objects such as `site.nav` and `hero.roles` are now expanded. It is semantically identical (deep-compare passes, and my own normalised diff shows only the §9 additions), so it is accepted. Don't re-flow it again in later tickets.
2. `scripts/serve.mjs:20`: `.listen(port)` binds every interface, so the dev preview is reachable on the LAN. Use `.listen(Number(process.env.PORT ?? 4321), '127.0.0.1')` and print the URL once.
3. `test/*.test.mjs` hard-code `/tmp/` in `mkdtemp`. Use `path.join(os.tmpdir(), 'tpct-build-')`.
4. `src/lib/validate.mjs:41`: `array(c.categories, …)` is called, and then `stringArray` calls `array` again, so a non-array `categories` reports the error twice. Call `stringArray` once and reuse its result.
5. URL fields (`hero.ctaTertiary.href`, `contact.github`, `contact.website`, `experience[].orgUrl`) are attr-escaped, and the CSP blocks `javascript:`. Still, validate them as `^https://`, and `ctaSecondary.href` as `^mailto:`, so a content typo fails the build. Can go in T-002/T-003.
6. `20-nav.js`: the outside-click handler calls `close(false)` on every page click even when the menu is closed. Guard it with `aria-expanded === 'true'`.
7. `40-hero.css`: the `bus-in` `scaleY` animation also runs on the md horizontal bus, where it has no visible effect. Consider scoping it to `min-width: 1024px`, or use `scaleX` at md.
8. Forced colours: the accent squares (brand, eyebrow, origin node) are pure backgrounds and disappear under `forced-colors: active`. Add `forced-color-adjust: none` or a `CanvasText` border in that media block. QA can confirm.
9. The base menu panel draws a double rule under the last link (link `border-block-end` + panel `border-block-end`). Use `#primary-nav li:last-child a { border-block-end: 0; }`.
10. `.no-js .site-header { position: static }` applies at every width. The spec only needs it at base. This is harmless and acceptable.
