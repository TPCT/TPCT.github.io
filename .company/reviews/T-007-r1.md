## Non-blocking suggestions
- 60-motion.js / 61-pointer.js have the same packed style, with one-letter names for everything (`L,x,E,F,b,q,M,w,A,S,k,B`). Expand the names in the parallax/glow block at least (`heroRect, heroVisible, raf, tx, ty, px, py, gx, gy, glowTx, glowTy, glowOn`) if the raised cap allows.
- 61-pointer.js:3 — the separate `matchMedia('(pointer: fine)')` check is redundant with the `(hover: hover) and (pointer: fine)` check. It exists only to satisfy the test regex. Relax the test regex to `/pointer: fine/` and drop the duplicate.
- Magnet edge case: when you move toward the far edge of a translated button, the pointer leaves the shifted hit box and the button snaps back (seen as `pointerleave` after `--mx:-6px`). This is acceptable per spec. If it looks jittery, use an invisible `::before` hit-area inset of -8px.
- Cursor glow is forced off whenever the hero is offscreen (`P()` includes hero visibility), so the "page-wide" glow only exists in the hero viewport. This matches "stops when the hero is offscreen". Mention it to the owner or decouple the glow loop from hero visibility.
- 15-motion.css: `main, .site-footer { position: relative; z-index: 1 }` creates a stacking context for all of main. Nothing broke today, but any future fixed overlay inside `main` (toast, modal) will sit under the header (z-index 50).
- Codex added `layout.mjs` outside the T-007 file whitelist. The addendum required it, so it is fine.
